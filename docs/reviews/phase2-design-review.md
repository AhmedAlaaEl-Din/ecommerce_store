# Independent design and UX review, Phase 2 (checkpoint, step 14)

A fresh general-purpose subagent got only the brief: "Review screenshots in evidence/phase2/review
against docs/DESIGN.md. List the 10 most important checkout UX problems, with fixes." It looked at all 23
screenshots and changed no files.

| #   | Finding (summary)                                                                                                    | Decision     | What changed                                                                                                                                                                                                                                                     |
| --- | -------------------------------------------------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Errors stay on fields that have already been fixed                                                                   | Fixed        | Editing a field clears its error, red border and `aria-invalid` immediately. The summary box hides once nothing is left in it. The server validates again on submit. E2E-tested.                                                                                 |
| 2   | Decline copy points at the address; internal wording; button unchanged                                               | Fixed        | "Your payment was declined. Nothing was charged and your details are saved below." uses `role="alert"`. The button reads "Try payment again · $X" after a decline or cancel. The not-completed order page now says "Nothing was charged and your cart is saved." |
| 3   | Sold-out cart: header badge still showed 1; "some items" for one item                                                | Mostly fixed | The cart page syncs the badge with the server count. The alert names the single product ("Sorry, the Ibis Enamel Teapot sold out…"). The empty-state text is unchanged, because the alert directly above it already explains what happened.                      |
| 4   | The "Confirming" page can feel stuck; no amount; no demo banner after payment                                        | Fixed        | Shows the total and item count. The "Still waiting? Your order is saved…" message plus "Check again" appear when polling ends (after 30 s, as the spec sets). Order pages for mock orders now show the demo ribbon too.                                          |
| 5   | Sale savings shown in the cart disappear at checkout                                                                 | Fixed        | A "Sale savings" row (accent colour, as in the cart) was added to the checkout summary, on desktop and mobile.                                                                                                                                                   |
| 6   | The error summary is long on mobile and its bullets were misaligned                                                  | Fixed        | The summary now shows a count ("Please check 6 fields:") and a compact, wrapping row of field links (each at least 24 px tall). Full messages stay inline under each field.                                                                                      |
| 7   | Full shop navigation and footer during checkout                                                                      | Rejected     | Kept on purpose for Phase 2. The header keeps the cart and recovery paths one tap away, and the demo needs the shop chrome to look continuous. A reduced checkout layout is noted as a Phase 3 polish item.                                                      |
| 8   | Mobile summary has no "Edit cart"; desktop link too small; quantity shown twice                                      | Fixed        | Shared `SummaryFootnote` with a 44 px "Edit cart" link in both summaries. The quantity badge on thumbnails was removed ("Qty N" stays).                                                                                                                          |
| 9   | Developer text and the accent colour on the mock page; "test mode" vs "mock" wording                                 | Fixed        | The note now reads "Demo only: a real store would show a secure card form here." The banner uses the neutral ink colour, and the required text is unchanged. The cart note says "mock or test-mode payments".                                                    |
| 10  | The confirmation uses the sale colour for "Order confirmed"; no demo note on the total; no next steps; address order | Mostly fixed | The label now uses the success colour. "Total paid (mock payment / test mode)". A "What happens next" block was added. The address format (postcode before town) is kept, because it is a common convention and the countries are invented.                      |
