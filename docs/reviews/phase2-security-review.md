# Independent security review, Phase 2 (checkpoint, step 13)

A fresh general-purpose subagent got only the brief: "Review the checkout, order, payment and webhook
code for: price or amount tampering, race conditions on stock, webhook signature handling, idempotency,
IDOR on order pages, CSRF, PII in logs, and secrets. List findings with file, line and fix. Do not edit
files." It worked read-only and made no network calls.

**Headline:** no critical issues. The reviewer confirmed these hold:

- Prices and totals are read from the database inside the reservation transaction.
- Stock decrements are conditional, and stock is released exactly once.
- Signatures are verified on the raw body.
- Idempotency is transactional.
- Order tokens are 192-bit and only work in the token holder's browser where it matters.
- Redirects use the configured URL, never the Host header.
- Live Stripe keys are refused.

| 1   | A cart can hold several pending orders: stock held twice, two payable sessions after "Back"                  | Medium-high | Fixed (per cart)      | `createPendingOrder` first cancels the cart's earlier pending order inside the same transaction, releasing its stock. | 4   | "Ignored" events were recorded as processed and could never be retried                                       | Medium-low  | Fixed                 | An event id is stored only after the order and session match. | 7   | Paying cleared items added to the cart after checkout                                                        | Low         | Fixed                 | Only the purchased quantities are removed.                                                                                                                                                                                                                                                      |
